ERROR #1

Nombres de una sola letra

x , n , d , tmp
Usar una sola letra como nombre no comunica nada sobre el dato que almacena. Quien lea el código —incluyendo tú mismo tres días después— no sabrá qué representa.
INCORRECTO ✕ 
function calc(x, n) {
  let t = 0;
  for (let i = 0; i < n; i++) {
    t += x[i];
  }
  return t / n;
}

// ¿Qué es x? ¿Qué es n?
// ¿t es temperatura, total, tiempo?
// i sólo está bien en un bucle corto
CORRECTO ■ 
function calculateAverage(numbers, count) {
  let total = 0;
  for (let index = 0; index < count; index++) {
    total += numbers[index];
  }
  return total / count;
}

// Ahora es completamente legible:
// numbers = arreglo de números
// total   = acumulador de la suma
// count   = cuántos elementos hay
x customerAge
edad del cliente
d orderDate
fecha del pedido
tmp temporaryFile
archivo temporal

ERROR #2

Mezcla de convenciones

snake_case PascalCase ALLCAPS
Cada lenguaje tiene sus propias convenciones de nombrado. Mezclarlas en el mismo archivo o proyecto genera inconsistencia que dificulta la lectura y mantenimiento del código.
INCORRECTO ✕ 
// Mezcla caótica de estilos
const user_name = "Ana";
const UserAge = 22;
const USEREMAIL = "ana@mail.com";

function Get_User_Data() { }
function processuser() { }
function UpdateUSER() { }

class student_record { }
class UserManager { }
class REPOSITORY { }
CORRECTO ■ 
// JavaScript → camelCase para variables/funciones
//              PascalCase para clases
const userName = "Ana";
const userAge = 22;
const userEmail = "ana@mail.com";

function getUserData() { }
function processUser() { }
function updateUser() { }

class StudentRecord { }
class UserManager { }
class Repository { }

ERROR #3

Abreviaciones crípticas

usrNm · calcTtl · prdLst
Acortar nombres para ahorrar caracteres resulta contraproducente: el tiempo que se gana escribiendo se pierde leyendo. Los editores modernos tienen autocompletado — no hay excusa para abreviar.
INCORRECTO ✕ 
function procOrd(usrNm, prdLst, dscnt) {
  const subTtl = calcTtl(prdLst);
  const fnlPrc = applyDscnt(subTtl, dscnt);
  const ordConf = genConf(usrNm, fnlPrc);
  return ordConf;
}

// ¿procOrd = process order? ¿procedure ordinary?
// ¿usrNm  = username? ¿user number?
// ¿fnlPrc = final price? ¿final process?
CORRECTO ■ 
function processOrder(userName, productList, discount) {
  const subtotal = calculateTotal(productList);
  const finalPrice = applyDiscount(subtotal, discount);
  const orderConfirmation = generateConfirmation(
    userName, finalPrice
  );
  return orderConfirmation;
}

// Perfectamente legible, sin ambigüedad alguna.
// El autocompletado escribe el resto por ti.

ERROR #4

Nombres que no reflejan el propósito

data · temp · info · doStuff
Nombres genéricos como data, temp, info o doStuff no dicen nada sobre el contenido o acción. El nombre debe responder "¿qué hay aquí?" o "¿qué hace esto?".
INCORRECTO ✕ 
const data = fetchFromAPI("/users");
const temp = data.users;
const info = temp.filter(x => x.value > 100);

function doStuff(thing) {
  return thing * 2;
}

function handle(e) {
  process(e);
}

class Manager {
  do() { }
}
CORRECTO ■ 
const apiResponse = fetchFromAPI("/users");
const allUsers = apiResponse.users;
const premiumUsers = allUsers.filter(
  user => user.score > 100
);

function doubleScore(currentScore) {
  return currentScore * 2;
}

function handleLoginClick(event) {
  authenticateUser(event);
}

class UserAccountManager {
  deactivateAccount() { }
}
REGLA PARA VARIABLES

El nombre debe responder ¿qué contiene este dato? Si no puedes responder sin ver el código, renómbralo.

REGLA PARA FUNCIONES

El nombre debe responder ¿qué acción realiza? Usa verbos: get, create, update, delete, calculate, validate…

ERROR #5

Booleanas sin prefijo is/has/can

is has can should
Una booleana sin prefijo no se lee como pregunta. Con el prefijo correcto, el código se lee como lenguaje natural: if (isLoggedIn) vs if (loggedIn) — la primera se entiende instantáneamente.
INCORRECTO ✕ 
const loggedIn = true;
const admin = false;
const visible = true;
const loading = false;
const active = true;

function validate(user) {
  return user.age >= 18;
}

if (loggedIn && admin) {
  showPanel();
}
CORRECTO ■ 
const isLoggedIn = true;
const isAdmin = false;
const isVisible = true;
const isLoading = false;
const isActive = true;

function canValidate(user) {
  return user.age >= 18;
}

if (isLoggedIn && isAdmin) {
  showAdminPanel();
}

Estado actual
isLoggedIn, isActive, isEmpty
has___
Posesión
hasPermission, hasChildren
can___
Capacidad
canEdit, canDelete, canView
should___
Decisión
shouldRedirect, shouldRetry

Todos los errores en un solo código

CON TODOS LOS ERRORES ✕ 
class user_Manager {       // ✗ Error 2: snake_case
  constructor() {
    this.d = [];            // ✗ Error 1: una letra
    this.active = false;   // ✗ Error 5: sin prefijo
  }

  AddUsr(n, a, e) {        // ✗ Error 1+2: letras+mezcla
    const usrObj = {       // ✗ Error 3: abreviación
      nm: n,               // ✗ Error 3: críptico
      ag: a,
      em: e
    };
    const temp = this.chk(a); // ✗ Error 4: nombre vago
    if (temp) {
      this.d.push(usrObj);
    }
  }

  chk(x) {                 // ✗ Error 1+3+4: triple error
    return x >= 18;
  }
}
CÓDIGO CORREGIDO ■ 
class UserManager {            // ✓ PascalCase
  constructor() {
    this.users = [];           // ✓ nombre descriptivo
    this.isActive = false;    // ✓ prefijo is
  }

  addUser(name, age, email) { // ✓ camelCase + descriptivo
    const newUser = {          // ✓ claro
      name: name,              // ✓ sin abreviaciones
      age: age,
      email: email
    };
    const isValidAge = this.validateAge(age); // ✓ is + descriptivo
    if (isValidAge) {
      this.users.push(newUser);
    }
  }

  validateAge(age) {          // ✓ verbo + descriptor
    return age >= 18;
  }
}

CIERRE

Resumen de Buenas Prácticas

Regla de oro
"El código se lee más de lo que se escribe"

Nombres descriptivos

Nunca uses x, n, d o tmp. Escribe lo que el dato representa.

01

Convención consistente

Elige un estilo (camelCase, snake_case) y úsalo en todo el proyecto.

02

Sin abreviaciones

Escribe las palabras completas. El autocompletado es tu aliado.

03

El nombre = propósito

Si necesitas un comentario para explicar un nombre, es un mal nombre.

04

Prefijos en booleanas

Usa is, has, can, should para que se lean como preguntas.

05
Código limpio no es solo código que funciona — es código que cualquier persona puede leer, entender y mantener. Nombrar bien es la habilidad más subestimada de la programación.
